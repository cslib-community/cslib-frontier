# Dynamic programming and string algorithms

Part of the [representative algorithm endpoints](algorithm-endpoints.md); the conventions and limitations stated there apply to this page.

## Context-free membership and CYK

Like Bellman–Ford, this is a pure Lean function with a `TimeM` cost model, not a machine program.

- **Grammars in Chomsky normal form.** Import `CslibFrontier.Computability.Languages.ChomskyNormalForm` ([source](../../CslibFrontier/Computability/Languages/ChomskyNormalForm.lean)). A `ChomskyNormalFormGrammar` has a list of rules `A → a` (`leaf`) and `A → B C` (`node`), and a flag `nilRule` for the rule `S → ε`. Sipser's definition ([Sipser][sipser13], Definition 2.8) forbids the start symbol on every right-hand side; the bundled invariant forbids it only when `nilRule` is set, so Hopcroft, Motwani and Ullman's `ε`-free form, with the start symbol allowed on right-hand sides, is covered too. `toCFG` reads the grammar as a Mathlib `ContextFreeGrammar`, and every statement is about Mathlib's `Derives` and `language` for it. `derives_iff_of_ne_nil` describes the derivations of a nonempty word by a first rule and a split. It rests on `ContextFreeGrammar.derives_append_iff` in [Foundations/Computability/ContextFreeGrammar.lean](../../CslibFrontier/Foundations/Computability/ContextFreeGrammar.lean), which splits a derivation from `u ++ v` into derivations from `u` and from `v`.
- **CYK.** Import `CslibFrontier.Algorithms.Lean.CYK.Basic` ([source](../../CslibFrontier/Algorithms/Lean/CYK/Basic.lean)). `cyk G w` fills the table of nonterminals deriving each subword, level by level, following [Kasami][kasami65], [Younger][younger67] and [Hopcroft, Motwani and Ullman][hmu06], Section 7.4.4. `mem_table_iff` says that each cell lists exactly the nonterminals deriving its subword. `cyk_eq_true_iff` says that `cyk G w = true` iff `w ∈ G.toCFG.language`, and `decidableMemLanguage` makes membership decidable. `time_cykM` gives the exact cost `(|R| + 1) (n + C(n + 1, 3))` for `|R|` rules and a word of length `n`, and `time_cykM_le` bounds it by `(|R| + 1) (n + 1)³`. One unit is charged per rule examined in each scan, and per split point (or letter) read. Table reads and writes, cell membership tests and insertions are constant-time steps, as on a RAM holding an array of nonterminal sets. Insertion skips nonterminals already present, and `nodup_table_and_length_le` shows that every cell is a list without repetitions of at most `|R|` nonterminals. The pure `cyk` is a specification for proofs and `decide`, not a fast executable (its table is a chain of function updates); the cost statements concern `cykM`.

The [CYK examples](../../CslibFrontierTests/Algorithms/Lean/CYK.lean) decide accepted and rejected words, including the empty word, for `{aⁿbⁿ}` and for balanced parentheses with `S → ε`, using `decide`, and check exact tick counts. This is the algorithm of [Sipser][sipser13], Theorem 7.16 (every context-free language is in P) **only for grammars already in Chomsky normal form**. Conversion of arbitrary grammars, a machine-level `ComputableInPolyTime` decider, Valiant's subcubic parsing, the pumping lemma, and CFG emptiness and universality are not formalized ([ROADMAP](../../roadmap/complexity.md#structure-time-and-space), [#3303](https://github.com/cslib-community/cslib-frontier/issues/3303)).

## Edit distance and longest common subsequence

Pure mathematical definitions and witnesses live in `CslibFrontier.Algorithms.Lean.EditDistance.*`, and checked Word-RAM programs and running-time bounds live in `CslibFrontier.Algorithms.WordRAM.EditDistance` ([source](../../CslibFrontier/Algorithms/WordRAM/EditDistance.lean)).

- **Tables over pairs of suffixes.** Import `CslibFrontier.Algorithms.Lean.EditDistance.Grid` ([source](../../CslibFrontier/Algorithms/Lean/EditDistance/Grid.lean)). A `GridDP` holds the four rules of a table indexed by pairs of suffixes of two words: the corner, the two borders, and the interior entry from its three neighbours. `GridDP.value` fills the table row by row, and the row of `a :: x` is computed from the row of `x` alone. The textbook tables are indexed by prefixes. Indexing by suffixes is the same program run on the reversed words. `value_cons_cons` and the border lemmas restate the rules.
- **Edit distance (Wagner–Fischer).** Import `CslibFrontier.Algorithms.Lean.EditDistance.Basic` ([source](../../CslibFrontier/Algorithms/Lean/EditDistance/Basic.lean)). `Costs α` gives arbitrary natural-number costs `del`, `ins` and `sub`. `Costs.unit` gives the Levenshtein distance. `Costs.indel` charges `1` per insertion or deletion and `2` per replacement by a different letter; such replacements are allowed, and `optScript Costs.indel` may return them. An `EditScript` is a list of operations `del a`, `ins b`, `sub a b`, with `src`, `tgt` and `cost`. This is an alignment, or a trace in the sense of [Wagner and Fischer][wagnerfischer74]. `editDist C x y` is the table entry, with the recurrence `editDist_cons_cons` (see also [CLRS][clrs09], Problem 15-5, and [Kleinberg and Tardos][kleinbergtardos06], Section 6.6). `isLeast_editDist` says that `editDist C x y` is the least cost of a script from `x` to `y`. The lower bound is `editDist_le_cost`. `optScript` reads an optimal script off the table (`src_optScript`, `tgt_optScript`, `cost_optScript`).
- **Longest common subsequence.** Import `CslibFrontier.Algorithms.Lean.EditDistance.LCS` ([source](../../CslibFrontier/Algorithms/Lean/EditDistance/LCS.lean)). `lcsLength x y` is the table of [CLRS][clrs09], Section 15.4, whose recurrence is `lcsLength_cons_cons` (Theorem 15.1). Subsequences are `List.Sublist`. `isGreatest_lcsLength` says that `lcsLength x y` is the greatest length of a common subsequence. The upper bound is `length_le_lcsLength`, and `lcs` reads a witness off the table (`lcs_spec`). `editDist_indel_add_two_mul` is the duality `editDist Costs.indel x y + 2 · lcsLength x y = |x| + |y|`. `isLeast_editDist_indel` shows that replacements gain nothing under `Costs.indel`: `splitSubs` turns each into a deletion and an insertion at the same cost, so `editDist Costs.indel x y` is also the least cost of a script without them (`EditScript.IsIndel`), the insertion–deletion distance.
- **Word-RAM running times.** Import `CslibFrontier.Algorithms.WordRAM.EditDistance` ([source](../../CslibFrontier/Algorithms/WordRAM/EditDistance.lean)). Over `Basis.standard` with one `(n + 1)`-word working row, `computesInTime_weightedEditDist` (`uniformComputableInTime_weightedEditDist`) proves that `weightedEditDistProgram` computes `editDist I.costs I.src I.tgt` for arbitrary letter costs over `Fin σ` (`WeightedInstance`) in at most `28 * (|x| + 1) * (|y| + 1)` instructions whenever working-row addresses and candidate DP sums fit in `w` bits (`WeightedInstance.FitsWidth`). Over arbitrary word-encoded sequences `WordSeqPair` (`[|x|, |y|] ++ x ++ y`), `computesInTime_unitEditDist` and `computesInTime_lcsLength` (`uniformComputableInTime_unitEditDist`, `uniformComputableInTime_lcsLength`) prove `26 * (|x| + 1) * (|y| + 1)` and `20 * (|x| + 1) * (|y| + 1)` instruction bounds under `WordSeqPair.FitsWidth`.

The [examples](../../CslibFrontierTests/Algorithms/Lean/EditDistance.lean) use `decide`. They check kitten/sitting (`3`, with its traceback), flaw/lawn (`2`), and empty words. They check costs that are neither unit nor symmetric, where a replacement beats a deletion plus an insertion but a swap does not. They check the strings of the running example of CLRS Section 15.4 (`lcsLength = 4`), a replacement returned by `optScript Costs.indel` next to an equal-cost script without it, and concrete flat-interpreter Word-RAM runs and `Program.ComputesInTime` certificates.

**Scope.** Costs are arbitrary: no triangle inequality or symmetry is assumed. The theorem is the trace (alignment) form of Wagner–Fischer. The equivalence with sequences of edit operations applied at arbitrary positions, which Wagner and Fischer prove under their cost conditions, is not formalized. For unit costs, neither the metric properties nor the characterization as the least number of single-letter edits is formalized. Also not formalized: Hirschberg's linear-space recovery of an optimal alignment, a machine-level `ComputableInPolyTime` statement, and the `OV` hardness of edit distance and LCS ([#3472](https://github.com/cslib-community/cslib-frontier/issues/3472), [#3037](https://github.com/cslib-community/cslib-frontier/issues/3037)).

## Optimal binary search trees and the Knuth–Yao speedup

Pure optimality and root-monotonicity theorems live in `CslibFrontier.Algorithms.Lean.OptimalBST.*`, and checked Word-RAM programs and `O(n³)` / `O(n²)` running-time bounds live in `CslibFrontier.Algorithms.WordRAM.OptimalBST` ([source](../../CslibFrontier/Algorithms/WordRAM/OptimalBST.lean)).

- **The recurrence.** [Basic.lean](../../CslibFrontier/Algorithms/Lean/OptimalBST/Basic.lean) works with an arbitrary interval weight `w : ℕ → ℕ → β` over a linearly ordered additive monoid. `IsBST i j t` says that `t : BinaryTree ℕ` is a search tree whose keys are exactly `i + 1, …, j` (`isBST_iff` relates it to the `Cslib.DataStructure.SearchTree` invariant). `treeCost w i j t` charges `w i' j'` at each node whose subtree holds the keys `i' + 1, …, j'`. For access weights `p` and failure weights `q`, `knuthWeight p q i j = ∑_{i<k≤j} p k + ∑_{i≤g≤j} q g`. `treeCost_knuthWeight` shows that this weight gives the weighted search cost: `p k` times the depth of key `k` plus one, plus `q g` times the number of keys compared by an unsuccessful search in gap `g`. The expected cost `e[1, n]` of [CLRS][clrs09], Section 15.5, also counts the dummy leaf, so it is this cost plus `∑ q g`. `optCost` is the recurrence `c(i, j) = w(i, j) + min_{i<k≤j} (c(i, k−1) + c(k, j))`. `isLeast_optCost` proves that it is the least cost of a tree on the keys, attained by `optTree`, which is read off the largest minimizing roots `optRoot`. No hypothesis on `w` is needed.
- **Yao's lemma and root monotonicity.** [Yao.lean](../../CslibFrontier/Algorithms/Lean/OptimalBST/Yao.lean) defines `QuadrangleIneq` and `MonotoneOnIntervals`. `quadrangleIneq_optCost` says that when `w` has both properties, `optCost w` satisfies the quadrangle inequality [Yao 1980][yao80b]. In an ordered cancellative monoid, `optRoot_mono` then gives `optRoot w i (j−1) ≤ optRoot w i j ≤ optRoot w (i+1) j` for the largest optimal roots, which is Knuth's monotonicity theorem for this problem [Knuth 1971][knuth71]. `knuthWeight` satisfies the quadrangle inequality with equality (`knuthWeight_add_knuthWeight`), and it is monotone on intervals when `p, q ≥ 0`.
- **Pure dynamic programs.** [Knuth.lean](../../CslibFrontier/Algorithms/Lean/OptimalBST/Knuth.lean) fills the table by increasing interval length. The cubic dynamic program `plainBST` returns `(optCost w 0 n, optTree w 0 n)` for every weight (`plainBST_eq`, `isOptimal_plainBST`). Knuth's `knuthBST` scans only the window `optRoot(i, j−1), …, optRoot(i+1, j)`. Under the two hypotheses it returns the same solution (`knuthBST_eq`, `isOptimal_knuthBST`), and along each diagonal its window lengths sum to at most `2n` (`sum_knuth_window_le`) because the windows telescope. `knuthBST_knuthWeight` packages optimality for nonnegative `p` and `q`. The constant `2` is not Knuth's sharper count.
- **Word-RAM running times.** [WordRAM/OptimalBST.lean](../../CslibFrontier/Algorithms/WordRAM/OptimalBST.lean) encodes an `n`-key instance `OptimalBSTInstance` as `[n] ++ weightTable` (`OptimalBSTInstance.ofWeight` restricts any `w : ℕ → ℕ → ℕ` while preserving `QuadrangleIneq` and `MonotoneOnIntervals`) and maintains `(n + 1)²`-word `cost` and `root` tables in memory above the input. Under `OptimalBSTInstance.FitsWidth`, `computesInTime_plainBST` (`uniformComputableInTime_plainBST`) proves that `plainBSTProgram` computes `(plainBST I.weightFn I.numKeys).cost` for every instance in at most `17 * (n + 1) ^ 3` standard-basis instructions, and `executes_knuthBST` (`computesInTime_knuthBST`, `uniformComputableInTime_knuthBST`) proves that `knuthBSTProgram` computes `(knuthBST I.weightFn I.numKeys).cost` in at most `58 * (n + 1) ^ 2` instructions whenever `I.weightFn` satisfies `QuadrangleIneq` and `MonotoneOnIntervals` (`OptimalBSTInstance.IsKnuthValid`).

The [tests](../../CslibFrontierTests/OptimalBST.lean) check both algorithms on the five-key example of [CLRS][clrs09], Section 15.5 (weights scaled by 100). Both return cost `235`, so `e[1, 5] = 2.75`. The returned tree has root `4`, whereas CLRS draws the root `k₂`; both trees cost `235`. The tests also check both algorithms against brute force over all search trees for `n ≤ 4`, verify Word-RAM `Executes` and `Cslib.WordRAM.run` certificates for `plainBSTProgram` and `knuthBSTProgram` (including `n = 0` and asymmetric weights), and verify three counterexample weights showing that each hypothesis is needed: if both fail, or the weight is monotone but violates the quadrangle inequality, or it satisfies the inequality but is not monotone, `knuthBST` returns a cost above the optimum, while `plainBST` (and `plainBSTProgram`) stays optimal.

The Hu–Tucker and Garsia–Wachs `O(n log n)` algorithms for the alphabetic case (`p = 0`), Turing-machine `ComputableInPolyTime` packaging, and the SMAWK and Monge-matrix generalizations are not formalized. Neither is matrix-chain multiplication, whose cost does not satisfy the hypotheses in general.

## String algorithms

Exact matching against a single pattern is Knuth–Morris–Pratt ([Basic](../../CslibFrontier/Algorithms/Lean/KMP/Basic.lean), [Search](../../CslibFrontier/Algorithms/Lean/KMP/Search.lean), [WordRAM](../../CslibFrontier/Algorithms/WordRAM/KMP.lean); [CLRS][clrs09], Section 32.4). Over any `[DecidableEq α]`, `Basic.lean` proves border–period duality (`isProperBorderLen_iff_isPeriod`), the proper-border chain (`mem_borderChain_iff`), and the prefix-function recurrence (`borderLen_succ`), while `Search.lean` defines the pure failure table `computePrefix p` (`computePrefix_size`, `getElem_computePrefix`) and exact matcher `kmpMatches p t` / `kmpMatchesList p t` (`mem_kmpMatches_iff`, `pairwise_lt_kmpMatches`, `mem_kmpMatchesList_iff`), reporting all `0`-indexed shifts including `0, …, |t|` when `p` is empty. On the `Basis.standard` word RAM (`CslibFrontier.Algorithms.WordRAM.KMP`), `prefixProgram` writes `(computePrefix p.toArray).toList` as a length-prefixed array within `31 * |p| + 10` instructions at every word width fitting `2 * |p| + 1` (`prefixCode_exec`, `prefixProgram_computesListInTime`), and `searchProgram` computes `kmpMatchesList I.pat I.txt` on `SearchInput.encode` (`[|pat|, |txt|] ++ pat ++ txt`) within `31 * |pat| + 37 * |txt| + 23` instructions at every word width fitting `2 * |pat| + 2 * |txt| + 4` (`searchCode_exec`, `searchProgram_computesListInTime`), charging every fallback step via a matched-prefix potential (`10 * k`). The [KMP examples](../../CslibFrontierTests/KMP.lean) check the failure table of `ababaca`, adversarial fallback chains, overlapping matches, and empty-pattern and empty-text boundary cases at minimal word widths.

Suffix arrays index one text for many patterns. Import `CslibFrontier.Algorithms.Lean.SuffixArray.Basic`, `.Kasai` and `.Search` ([Basic](../../CslibFrontier/Algorithms/Lean/SuffixArray/Basic.lean), [Kasai](../../CslibFrontier/Algorithms/Lean/SuffixArray/Kasai.lean), [Search](../../CslibFrontier/Algorithms/Lean/SuffixArray/Search.lean)) for the pure algorithms over any `LinearOrder`, and `CslibFrontier.Algorithms.WordRAM.SuffixArray` ([WordRAM/SuffixArray.lean](../../CslibFrontier/Algorithms/WordRAM/SuffixArray.lean)) for the uniform Word-RAM programs over word arrays. In the pure modules, suffixes are ordered with Mathlib's lexicographic order on lists, so a proper prefix comes before the words that extend it. No end-of-word sentinel is assumed, and only the nonempty suffixes `w.drop i` with `i < |w|` are listed.

- **Specification.** `IsSuffixArray w sa` says that `sa` is a permutation of `List.range w.length` whose suffixes strictly increase [Manber and Myers][manbermyers93]. `IsSuffixArray.unique` shows that suffix arrays are unique. `suffixArray w` sorts the positions by their suffixes with `List.mergeSort`, and `isSuffixArray_suffixArray` proves it correct. This reference construction has no linear-time bound.
- **LCP array.** `lcpArray w sa` has `0` at rank `0` and the longest-common-prefix length (`List.lcpLen`, in [Foundations/Data/List/CommonPrefix.lean](../../CslibFrontier/Foundations/Data/List/CommonPrefix.lean)) of the suffixes of ranks `r - 1` and `r` at rank `r > 0`. `IsSuffixArray.getElem_lcpArray_sub_one_le` is the height lemma `lcp[rank[i + 1]] ≥ lcp[rank[i]] - 1` of [Kasai et al.][kasai01].
- **Kasai et al.'s algorithm.** `kasaiArray` and `kasai` visit positions in text order and extend each common prefix from the previous length minus one. `kasaiArray_toList` and `kasai_eq_lcpArray` show that they return `lcpArray` whenever `sa` is a suffix array. On the Word RAM, `kasaiProgram` builds the rank array in memory, scans the text with amortized potential `47 (|text| - i) - 14 min(h, |text| - i)`, and returns `kasai I.text I.sa` within `55 * |text| + 8 * |sa| + 26` instructions on every input (`kasaiProgram_computesListInTime`), hence `lcpArray I.text I.sa` within `63 * |text| + 26` instructions on a suffix array (`kasaiProgram_computesLcpArrayInTime`).
- **Pattern search.** `searchArray` and `search` run two binary searches (`lowerBound`, in [Query/BinarySearch.lean](../../CslibFrontier/Algorithms/Lean/Query/BinarySearch.lean)) and return a rank interval `[lo, hi)`. Each probe compares `p` with at most `|p|` characters of a suffix (`cmpSuffix`). `searchArray_spec` and `search_spec` show that the suffix of rank `r` starts with `p` exactly when `lo ≤ r < hi`, and `mem_occurrences` characterizes the matching text positions `occurrences w sa p`. On the Word RAM, [WordRAM/BinarySearch.lean](../../CslibFrontier/Algorithms/WordRAM/BinarySearch.lean) provides the reusable overflow-safe bisection combinator `bisectCode` (`bisectCode_exec`) and sorted-array search `lowerBoundProgram` (`13 * (Nat.log 2 |arr| + 1) + 14` instructions). Building on `bisectCode`, `rangeSearchProgram` computes `[lo, hi]` within `(32 * |pat| + 63) * (Nat.log 2 |sa| + 1) + 26` instructions (`rangeSearchProgram_computesListInTime`, `O(|p| log |sa|)` independent of occurrence count), and `occurrencesProgram` reports `occurrences` within `(32 * |pat| + 63) * (Nat.log 2 |sa| + 1) + 9 * |occurrences| + 27` instructions (`occurrencesProgram_computesListInTime`). This is the plain `O(|p| log n)` search. The `O(|p| + log n)` search, which reuses precomputed LCP information between probes, is not formalized.

For the empty pattern the search returns every position `i < |w|`. KMP also reports the position `|w|` of the empty suffix. The [examples](../../CslibFrontierTests/SuffixArray.lean) check `banana` and `mississippi`: the suffix and LCP arrays, pure and Word-RAM execution with instruction bounds, and agreement with KMP on several patterns. They also include kernel-checked `ExecutesList` witnesses, a suffix-array uniqueness check, a rejected non-sorted permutation, malformed suffix-array inputs, and absent and empty patterns. Linear-time construction (SA-IS, DC3), LCP-accelerated search and suffix trees remain open ([ROADMAP](../../roadmap/algorithms.md#string-algorithms)).

### The Z-algorithm

Import `CslibFrontier.Algorithms.Lean.ZFunction.Search` and `CslibFrontier.Algorithms.WordRAM.ZFunction` ([Basic.lean](../../CslibFrontier/Algorithms/Lean/ZFunction/Basic.lean), [Search.lean](../../CslibFrontier/Algorithms/Lean/ZFunction/Search.lean), [WordRAM](../../CslibFrontier/Algorithms/WordRAM/ZFunction.lean)). Over any `[DecidableEq α]`, the Z-function of a word `s` is `zFunction s`, whose entry at `i < |s|` is `List.lcpLen s (s.drop i)`. Positions are `0`-based and `z[0] = |s|`; [Gusfield][gusfield97] (§1.3–1.4) indexes from `1` and leaves `Z_1` undefined. `zArray s` and `zAlgorithm s` implement the Z-box scan of §1.4 (`min_lcpLen_zBox`, `zArray_toList`, `zAlgorithm_eq_zFunction`), keeping the rightmost box `[l, r)` that repeats a prefix of `s` and copying `z[i - l]` when `z[i - l] < r - i` or extending from `r - i` otherwise. On the `Basis.standard` word RAM, `zProgram` writes `zFunction s` as a length-prefixed array within `39 * |s| + 10` instructions at every word width fitting `2 * |s| + 1` (`zCode_exec`, `zProgram_computesListInTime`), charging every comparison, Z-box copy, and memory access via the potential `10 * (|s| - r) + 29 * (|s| - i)`.

For exact matching (§1.5), `zMatchesArray p t` and `zMatches p t` compute the Z-array of `p ++ t` and report the shifts `i ≤ |t|` whose value at `|p| + i` is at least `|p|`. Gusfield's separator `$` is not used, so values above `|p|` are allowed. `mem_zMatches_iff` characterizes the output and `zMatches_eq_kmpMatchesList` shows that it equals the KMP output (including the shift `|t|` for the empty pattern). On the word RAM, `matchProgram` computes `zMatches I.pat I.txt` (`= KMP.kmpMatchesList I.pat I.txt`) on `MatchInput.encode` (`[|pat|, |txt|] ++ pat ++ txt`) within `39 * |pat| + 50 * |txt| + 23` instructions at every word width fitting `2 * |pat| + 3 * |txt| + 4` (`matchCode_exec`, `matchProgram_computesListInTime`, `matchProgram_computesKmpMatchesInTime`). The [examples](../../CslibFrontierTests/ZFunction.lean) check Z-arrays and matching against KMP across Gusfield's running example, constant words, `a ^ (n - 1) b`, overlapping occurrences, and empty-pattern / empty-text / minimal-width boundary cases. Not formalized: linear conversions between Z-values and the KMP prefix function ([ROADMAP](../../roadmap/algorithms.md#string-algorithms)).

### Multi-pattern matching: Aho–Corasick

Import `CslibFrontier.Algorithms.Lean.AhoCorasick.Search` ([Basic.lean](../../CslibFrontier/Algorithms/Lean/AhoCorasick/Basic.lean), [Search.lean](../../CslibFrontier/Algorithms/Lean/AhoCorasick/Search.lean)). It formalizes the pattern matching machine of [Aho and Corasick][ahocorasick75] for a keyword list `P : List (List α)` over any alphabet with decidable equality. As in Section 4 of the paper, a state is represented by its string: the states are `[]` and the prefixes of keywords (`IsNode P`). The goto function sends `u` on `a` to `u ++ [a]` when that is a state, and the start state loops on every other symbol. The specification is `occurrences P t`: the pairs `(i, y)` with `y ∈ P` nonempty and a suffix of `t.take i`, so `i` is the `1`-indexed end position printed by Algorithm 1. Pairs are listed by increasing end position and, at one position, by decreasing length (`pairwise_occurrences`). A keyword listed twice in `P` is reported once per position, and the empty keyword is never reported.

The paper's lemmas are stated for the string representation:

- **Lemma 1:** `failure P u` is the longest proper suffix of `u` that is a state (`eq_failure_iff`).
- **Lemma 2:** `output P w` lists the keywords that are suffixes of `w` (`mem_output_iff`), and `output_eq_of_ne_nil` is the output recurrence of Algorithm 3.
- **Lemma 3:** the state after reading `w` is `longestNodeSuffix P w` (`foldl_nextMove`, and `longestNodeSuffix_append_singleton_eq_nextMove` for one cycle).

In [Search.lean](../../CslibFrontier/Algorithms/Lean/AhoCorasick/Search.lean), Algorithm 1 is `scan P M t`, which runs a machine `M` (failure and output tables, both functions on strings). `scan_eq_occurrences` shows that with valid tables (`Machine.IsValid`) the scan returns `occurrences P t`. The failure loop in `step` is guarded: a failure transition that does not shorten the state stops at the start state, which never happens with a valid table and guarantees termination for arbitrary tables. Algorithm 3 is `build P`, which computes the tables level by level, taking the failure state of `p.take (d + 1)` from that of `p.take d` by one operating cycle (`failure_append_singleton`). `isValid_build` proves the tables valid, and `search_eq` and `mem_search_iff` give the end-to-end pure specification `search P t = occurrences P t`.

For bounded integer alphabets `[0, σ)`, import `CslibFrontier.Algorithms.WordRAM.AhoCorasick` ([WordRAM/AhoCorasick.lean](../../CslibFrontier/Algorithms/WordRAM/AhoCorasick.lean)) for the `Basis.standard` Word-RAM realization (`searchCode` and `searchProgram`). An `Input` bundles `σ`, `P`, and `t` under `Input.Valid`, serialized by `Input.encode` (`Input.Valid.inputFits`). Execution builds a flat `maxS × σ` array trie (`maxS = totalPatternLen P + 1`, Algorithm 2), runs a single breadth-first queue pass over the reachable trie states computing failure links, the deterministic next-move table of Section 6, and linked output chains `(outHead, outNext)` without re-traversing shared prefixes (Algorithm 3), and scans `t` by Algorithm 1 using failure-depth potential and output-link walks to emit flat `[endPos, keywordLen]` pairs (`encodeOccurrences`, inverted on valid occurrences by `decodeOccurrences_encodeOccurrences`). `searchCode_exec`, `searchProgram_computesListInTime`, and `searchProgram_executesList` prove exact agreement with `encodeOccurrences (occurrences P t)` within `searchTime inp = O((‖P‖ + 1) · σ + |P| + |t| + occ)` machine instructions at any word width satisfying `Fits w inp.wordBound` (`wordBound_le`).

For one keyword, [KMP.lean](../../CslibFrontier/Algorithms/Lean/AhoCorasick/KMP.lean) connects the machine to the Knuth–Morris–Pratt matcher of [CslibFrontier/Algorithms/Lean/KMP](../../CslibFrontier/Algorithms/Lean/KMP/Search.lean). `failure_singleton_take` identifies the failure function with the KMP prefix function `borderLen`, and `search_singleton` shows that `search [p] t` is `kmpMatchesList p t` with each shift moved to its end position.

The [checked examples](../../CslibFrontierTests/AhoCorasick.lean) reproduce Figures 1 and 2 of the paper (`he`, `she`, `his`, `hers` on `ushers`) for both pure `search` and compiled Word-RAM `searchCode` evaluation, checking the failure and output functions, the three reported pairs, lossless `decodeOccurrences` recovery, and instruction-count bounds, alongside unary overlapping suffixes (`σ = 1`), duplicate and empty keywords, empty text/pattern lists, `σ = 0`, an invalid failure table that misses `hers`, and the KMP special case. Not formalized: compressed or comparison-based transition structures for sparse/unbounded alphabets, dynamic dictionary updates, and Turing-machine realizations ([ROADMAP](../../roadmap/algorithms.md#string-algorithms)).

### Palindromes and Manacher's algorithm

Import `CslibFrontier.Algorithms.Lean.Palindrome.Basic`, `CslibFrontier.Algorithms.Lean.Palindrome.Manacher` and `CslibFrontier.Algorithms.WordRAM.Manacher` ([Basic](../../CslibFrontier/Algorithms/Lean/Palindrome/Basic.lean), [Manacher](../../CslibFrontier/Algorithms/Lean/Palindrome/Manacher.lean), [WordRAM](../../CslibFrontier/Algorithms/WordRAM/Manacher.lean)). A word of length `n` has `2n + 1` centers `c = 0, …, 2n`: odd `c` is the letter at position `c / 2` and even `c` is the gap before it. The factor `w.extract a b` has center `a + b`. `radius w c` is the largest `k` such that `w.extract (c / 2 - k) ((c + 1) / 2 + k)` is a palindrome (Mathlib's `List.Palindrome`), and it is `0` for `c > 2n`. These are the even and odd maximal radii of [Apostolico, Breslauer and Galil][apostolicobreslauergalil95], Section 1, `0`-indexed and merged into one sequence. No sentinel letters are interleaved.

- **Specification.** `palindrome_extract_iff_le_radius` says that for `a ≤ b ≤ n` the factor `w.extract a b` is a palindrome iff `b - a ≤ 2 * radius w (a + b) + (a + b) % 2`. `longestPalindrome w` is the maximal palindrome about a center maximizing that length. `length_le_longestPalindrome`, `palindrome_longestPalindrome` and `longestPalindrome_isInfix` show that it is a longest palindromic factor. `palindrome_take_iff` reads the palindromic prefixes off the radii: `w.take k` is a palindrome iff `radius w k = k / 2`. The list lemmas behind these (`List.palindrome_extract_iff`, `List.Palindrome.extract_reflect` and others) are in [Palindrome.lean](../../CslibFrontier/Foundations/Data/List/Palindrome.lean).
- **Mirror lemma.** `min_radius_mirror` is the step of the algorithm. If the maximal palindrome about `C` ends at `R`, then for `c ≥ C` the radii about `c` and about `2C - c` agree after truncating both at `R - (c + 1) / 2`.
- **Algorithm and Word-RAM running time.** `manacher w` ([Manacher][manacher75]) scans the centers left to right, keeping the center whose palindrome reaches furthest right. It reuses the mirrored radius when that radius is below the truncation; otherwise `extend` compares letters outward. `manacher_eq` shows that `manacher w` is `Array.ofFn (radius w.toList ·)` over the `2 * w.size + 1` centers, and `longestPalindromeSpan w` gives the half-open interval `[start, stop)` of `longestPalindrome w.toList` (`extract_longestPalindromeSpan`). On the `Basis.standard` word RAM (`CslibFrontier.Algorithms.WordRAM.Manacher`), `radiiProgram` computes all `2 * |xs| + 1` radii `(manacher xs.toArray).toList` as a length-prefixed array within `87 * |xs| + 16` instructions at every word width fitting `3 * |xs| + 2` (`radiiCode_exec`, `radiiProgram_computesListInTime`), using a potential on `|xs| - R` so that successful outward letter matches sum to at most `|xs|`. `longestProgram` scans the radii for `bestCenter xs`, places `longestPalindromeSpan xs.toArray` in registers `(regl, regr)` and copies out `longestPalindrome xs` within `116 * |xs| + 37` instructions at every width fitting `4 * |xs| + 4` (`longestCode_exec`, `longestProgram_computesListInTime`).

The [examples](../../CslibFrontierTests/Manacher.lean) check the radii of `abacaba`, `abba`, `aaaa`, `abcd` (all `0`), the empty word and a one-letter word by `decide` through `manacher_eq`, one extension phase, the longest palindrome of `xabacabay`, a palindromic and a non-palindromic prefix, and Word-RAM runs and non-vacuity instances of `radiiProgram` and `longestProgram` including minimal-width empty inputs. Manacher's original algorithm is on-line: it reports the palindromic prefixes as letters arrive. That formulation, palindromic trees (eertrees) and parallel algorithms are not formalized ([ROADMAP](../../roadmap/algorithms.md#string-algorithms)).

## Lempel–Ziv incremental parsing (LZ78)

Import `CslibFrontier.Algorithms.Lean.LempelZiv.LZ78Bits`. The parse and pair code are in [LZ78.lean](../../CslibFrontier/Algorithms/Lean/LempelZiv/LZ78.lean), which needs only list imports. The phrase count is in [LZ78Count.lean](../../CslibFrontier/Algorithms/Lean/LempelZiv/LZ78Count.lean), the bit code in [LZ78Bits.lean](../../CslibFrontier/Algorithms/Lean/LempelZiv/LZ78Bits.lean), and the alphabet-generic [distinct-parsing bound](../../CslibFrontier/Algorithms/Lean/LempelZiv/DistinctParsing.lean) in the namespace `DistinctParsing`. `LZ78.parse` is the incremental parsing of [Ziv and Lempel][zivlempel78] on `List α` for any type with decidable equality. Each phrase is the shortest prefix of the remaining input that is not an earlier phrase; when the input runs out first, the last phrase is the nonempty remainder and may repeat an earlier phrase. The phrases concatenate to the input (`flatten_parse`) and are nonempty. Each phrase is the shortest new prefix (`prefix_mem_take_parse`, `getElem_parse_notMem_take`), and the phrases before the last are pairwise distinct (`nodup_dropLast_parse`; all are distinct when the last phrase is new, `nodup_parse_of_getLast_notMem`). `LZ78.encode` writes phrase `w` as the pair (index of `w.dropLast` among `[]` and the earlier phrases, last symbol of `w`), and `decode_encode` says that `LZ78.decode` inverts it. `LZ78.encodeBits e` fixes a numbering `e : α ≃ Fin k` and writes the `i`-th pair with `⌈log₂ i⌉` pointer bits and `⌈log₂ k⌉` symbol bits, least significant bit first. `decodeBits_encodeBits` gives the round trip for `k ≥ 2`.

The bounds are for an alphabet of size `k ≥ 2`, an input of length `n` and `c` phrases. The basic inequality is `m * c ≤ n + 2 * k ^ m` for every `m` (`mul_length_le_of_nodup` for distinct parsings and `mul_length_parse_le` for LZ78, whose last phrase may repeat). Choosing `m` gives `c * ⌊log_k c⌋ ≤ n + 2c` (`length_parse_mul_log_le`) and `c (log_k n - log_k log_k n - 4) ≤ n` (`length_parse_mul_logb_sub_le`). It also gives `c ≤ n / ((1 - ε_n) log_k n)` for `n ≥ 2` and `ε_n < 1` (`length_parse_le_div`), where `epsilon k n = min 1 ((log_k log_k n + 4) / log_k n)` (`epsilon_def`) tends to `0` (`tendsto_epsilon`). For `k = 2` this is the distinct-parsing lemma of [Cover and Thomas][coverthomas06], §13.5; the general-`k` form, with logarithms to base `k`, is the same argument. The code length is exactly `∑_{i=1}^{c} (⌈log₂ i⌉ + ⌈log₂ k⌉)` (`length_encodeBits`). It is at most `c (⌈log₂ c⌉ + ⌈log₂ k⌉)` (`length_encodeBits_le`) and at most `⌈log₂ k⌉ (n + 4c)` (`length_encodeBits_le_mul_add`). It is also at most `⌈log₂ k⌉ n (1 + 4 / ((1 - ε_n) log_k n))` (`length_encodeBits_le_mul_one_add`), so LZ78 expands no input by more than a vanishing fraction over the fixed-length code (`exists_length_encodeBits_le`). The functions are reference implementations with list-based dictionary lookups, and no running time is claimed.

The [examples](../../CslibFrontierTests/Algorithms/Lean/LempelZiv.lean) check the Cover–Thomas input `ABBABBABBBAABABAA`: its phrases `A, B, BA, BB, AB, BBA, ABA, BAA`, its pairs, and its 25-bit code. They also cover the empty input and `AA`, whose repeated last phrase makes the parse not duplicate free. Further checks are a phrase list that is not tree structured, bit strings that fail to decode, `1 ^ 100` with 14 phrases and 55 bits, and an input length (`n = 256`) at which the `ε_n` hypotheses hold. Not formalized: optimality for stationary ergodic sources (Ziv's inequality, a compression ratio tending to the entropy rate), and the links to Kolmogorov complexity and finite-state compressibility ([ROADMAP](../../roadmap/pseudorandomness.md)). The sliding-window variant is in the next section.

## Lempel–Ziv sliding-window parsing (LZ77) and complexity (LZ76)

Import `CslibFrontier.Algorithms.Lean.LempelZiv.LZ77Count`. The parse and the triple code are in [LZ77.lean](../../CslibFrontier/Algorithms/Lean/LempelZiv/LZ77.lean), and the comparison with LZ78 is in [LZ77Count.lean](../../CslibFrontier/Algorithms/Lean/LempelZiv/LZ77Count.lean), both in the namespace `LZ77`. `Reproducible W h u` says that `u` is empty or is a copy that starts `d` symbols before the end of the text `h`, for some `1 ≤ d ≤ min W |h|`. The copy may run into `u` itself, as in [Lempel and Ziv][lempelziv76]. A history (`IsHistory`) is a factorization into nonempty phrases, each reproducible from the text before it except for its last symbol. A history is exhaustive (`IsExhaustive`) when no phrase but the last is reproducible. `LZ77.parse W` takes as each phrase the longest reproducible prefix of the rest of the input plus one symbol, or the whole rest if it is reproducible. It is an exhaustive history of its input (`flatten_parse`, `isHistory_parse`, `isExhaustive_parse`). By an exchange argument it has the fewest phrases among all histories with the same window (`length_parse_le_of_isHistory`), and it is the only exhaustive history (`parse_eq_of_isExhaustive`). `LZ77.complexity x` is the phrase count with window `|x|`. That window is unbounded for `x`, because a copy cannot start before the text. The complexity is the least number of phrases of a history (`complexity_le_of_isHistory`). `LZ77.encode W` writes each phrase as a triple (distance, length − 1, last symbol), as in [Ziv and Lempel][zivlempel77]. `decode_encode` says that `LZ77.decode` inverts it; the decoder copies symbol by symbol and does not need `W`.

When the window covers the input, every LZ78 phrase is an earlier phrase followed by one symbol, so the LZ78 parse is a history (`isHistory_lz78Parse`). Hence LZ77 needs no more phrases than LZ78 (`length_parse_le_length_parse`, `complexity_le_length_parse`), and the LZ78 distinct-parsing bound transfers: `c ≤ n / ((1 - ε_n) log_k n)` for `n ≥ 2`, `k ≥ 2` and `ε_n < 1` (`LZ77.length_parse_le_div`, `LZ77.complexity_le_div`). The window bounds only how far back a copy may start. Copies may be arbitrarily long, so the 1977 algorithm's lookahead buffer and fixed-width codewords are not modelled. No bit code or running time is claimed.

The [examples](../../CslibFrontierTests/Algorithms/Lean/LempelZivLZ77.lean) parse `ABBABBABBBAABABAA` into the seven phrases `A, B, BA, BBABBB, AA, BABA, A` (LZ78 uses eight) and check its triples and decoding. They also check the overlapping copy in `a ^ 8` (two phrases, against four for LZ78) and window `0`. The period-3 input `abcabcabc` needs nine phrases with window `2` and four with window `3`. Further checks are a history that is not exhaustive, a factorization that is not a history, and the `n = 256` instance of the bound. Not formalized: bit-level LZ77 codes with bounded match length, the optimality of LZ77 for stationary ergodic sources, and the links to Kolmogorov complexity and finite-state compressibility ([ROADMAP](../../roadmap/pseudorandomness.md)).

## Burrows–Wheeler transform

Import `CslibFrontier.Algorithms.Lean.BurrowsWheeler.Basic` ([source](../../CslibFrontier/Algorithms/Lean/BurrowsWheeler/Basic.lean)), `CslibFrontier.Algorithms.Lean.BurrowsWheeler.Decode` ([source](../../CslibFrontier/Algorithms/Lean/BurrowsWheeler/Decode.lean)), and `CslibFrontier.Algorithms.WordRAM.BurrowsWheeler` ([source](../../CslibFrontier/Algorithms/WordRAM/BurrowsWheeler.lean)). The transform follows Algorithm C of [Burrows and Wheeler][burrowswheeler94], Section 2, over any `LinearOrder` alphabet, with no end-of-word sentinel. `bwtMatrix w` sorts the rotations of `w` lexicographically, and `bwt w = (bwtLast w, bwtIndex w)` is the last column together with the index of the *first* row equal to `w`. The empty word maps to `([], 0)`. Periodic words have repeated rows, and are still handled.

The LF-mapping `lfMap L r = L.countP (· < L[r]) + (L.take r).count L[r]` is computed from the last column alone, as in Section 4.2 of the report. `rotate_one_getElem_bwtMatrix_lfMap` proves its row form: row `lfMap L r`, rotated left by one place, is row `r`. `getElem?_bwtFirst_lfMap` and `count_take_bwtFirst_lfMap` prove the occurrence form (step D2): the `k`-th `c` of `L` corresponds to the `k`-th `c` of the first column. `lfMap_bwtLast_injOn` and `map_lfMap_range_perm` show that the LF-mapping is a permutation of the rows, which completes step D2. `bwtFirst_eq_mergeSort_bwtLast` says that the first column is the sorted last column (step D1). `getElem?_bwtLast_iterate_lfMap` is the decoding formula `w[n - 1 - i] = L[T^[i] I]` (step D3). `inverseBwt_bwt` and `bwt_injective` state invertibility and injectivity of the transform with its index. `Decode.lean` gives the pure table-driven decoder `lfDecodeTable` and `inverseBwtTable` over `rankTable` (`inverseBwtTable_eq_inverseBwt`, `inverseBwtTable_bwt`). For bounded integer alphabets `[0, σ)` on the `Basis.standard` Word-RAM (`WordRAM/BurrowsWheeler.lean`), `buildTablesCode_exec` constructs both `C` and `rankTable L` in `11 * σ + 11 * |L| + 13` instructions, `lfDecodeCode_exec` runs the `|L|` LF-step lookups in `14 * |L| + 9` instructions, and `decodeCode_exec` and `decodeProgram_computesListInTime` invert an arbitrary input `inp = ⟨L, I, σ⟩` (`inp.encode = I :: σ :: L`) in at most `25 * |L| + 11 * σ + 34` machine instructions under `inp.Valid`, `Fits w (3 * |L| + σ + 4)`, and `InputFits w inp.encode` (which bounds the arbitrary encoded starting row `I`). On `bwt u`, `decodeProgram_bwt` discharges `InputFits` automatically from `bwtIndex u ≤ |u|` and recovers `u` under `∀ c ∈ u, c < σ` and `Fits w (3 * |u| + σ + 4)`. The sort of the forward transform is not costed on the Word-RAM.

The [examples](../../CslibFrontierTests/BurrowsWheeler.lean) check the report's running example (`abraca` ↦ `(caraab, 1)`, `T = (4 0 5 1 2 3)`), `banana`, the periodic word `cancan`, whose LF orbit `[2, 4, 0, 2, 4, 0]` repeats with period 3 and is not a permutation of the rows, the empty word, a single letter and a constant word. They also show that the last column alone is not injective. Not formalized: move-to-front and entropy coding, compression bounds in terms of empirical entropy, FM-index backward search, the link to suffix arrays, and charged construction of the transform ([ROADMAP](../../roadmap/algorithms.md#string-algorithms)).
